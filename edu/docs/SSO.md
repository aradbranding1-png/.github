# اتصال SSO به my.aradbranding.me

چون API رسمی my هنوز تحویل نشده، سامانه دو روش استاندارد را پیاده‌سازی کرده و همه آدرس‌ها و نگاشت فیلدها **از پنل** (سیستم → اتصال SSO) تنظیم می‌شود؛ بعد از دریافت مستندات my نیازی به تغییر کد نیست.

## موارد لازم از تیم my (چک‌لیست بررسی API)
| مورد | در سامانه |
|---|---|
| روش Authentication | OAuth2 Authorization Code (+PKCE) — یا — توکن JWT امضاشده HS256 |
| Endpoint ورود/Authorize | `sso_authorize_url` |
| Endpoint Token (OAuth2) | `sso_token_url` + `SSO_CLIENT_ID` / `SSO_CLIENT_SECRET` در .env |
| Endpoint اطلاعات کاربر | `sso_userinfo_url` (با Bearer توکن کاربر، یا `MY_API_KEY` برای فراخوانی سرور-به-سرور؛ `{id}` جایگزین می‌شود) |
| شناسه یکتای کاربر | نگاشت `sso_map_id` — **تنها معیار اتصال حساب‌ها** (ستون `users.my_user_id`، یکتا) |
| پروفایل | نگاشت نام، نام خانوادگی، موبایل، ایمیل |
| وضعیت حساب | `sso_map_status` + مقادیر فعال (کاربر غیرفعال در my وارد نمی‌شود) |
| Role | (اختیاری) نقش‌ها در edu مستقل مدیریت می‌شوند |
| عکس پروفایل | `sso_map_avatar` (URL) |
| Refresh Token | ذخیره نمی‌شود؛ نشست edu مستقل است |
| اعتبارسنجی توکن | OAuth2: state + PKCE + تبادل سمت سرور با TLS. JWT: امضای HS256، `exp`/`nbf`، جلوگیری از استفاده مجدد با `jti` |
| Logout | `sso_logout_url` (پس از خروج از edu، به my هدایت و برمی‌گردد) |
| دریافت اطلاعات به‌روز | در هر ورود SSO همگام می‌شود؛ API داخلی `POST /api/v1/users` نیز برای همگام‌سازی از سمت my وجود دارد |

آدرس بازگشت (Redirect URI) که باید در my ثبت شود: `https://edu.aradbranding.me/sso/callback`

## روش ۱ — OAuth2 (پیشنهادی)
1. تیم my یک Client برای edu بسازد (Laravel Passport) با Redirect بالا.
2. در `.env`: `SSO_CLIENT_ID` و `SSO_CLIENT_SECRET`.
3. در پنل: روش OAuth2، آدرس‌های authorize/token/userinfo، نگاشت فیلدها (مثال Passport: `id`, `first_name`, `last_name`, `mobile`, `email`, `avatar`)، فعال‌سازی.

## روش ۲ — JWT
my پس از ورود کاربر، او را به `https://edu.aradbranding.me/sso/callback?state=<همان state دریافتی>&token=<JWT>` هدایت می‌کند. edu کاربر را با پارامترهای `return_url` و `state` به `sso_authorize_url` می‌فرستد.
```
header : {"alg":"HS256","typ":"JWT"}
payload: {"sub":"12345","given_name":"...","family_name":"...","phone":"0912...","email":"...","avatar":"https://...","exp":<now+300>,"jti":"<random>"}
امضا   : HMAC-SHA256 با SSO_SHARED_SECRET (حداقل ۳۲ کاراکتر، مشترک بین my و edu)
```

## قواعد اتصال حساب‌ها (جلوگیری از حساب تکراری)
1. اگر `my_user_id` قبلاً به حسابی متصل است → ورود همان حساب.
2. اگر کاربر در edu وارد است و از پروفایل «اتصال حساب» را زده → اتصال به همان حساب.
3. اگر حسابی با **همان موبایل/ایمیل** در edu وجود دارد → اتصال خودکار انجام **نمی‌شود**؛ کاربر باید رمز حساب edu را وارد کند (اثبات مالکیت). سپس همه سوابق حفظ می‌شود.
4. در غیر این صورت (و اگر فعال باشد) حساب جدید با نوع پیش‌فرض ساخته می‌شود.
5. ادغام دستی دو حساب (Link/Merge) از صفحه کاربران توسط مدیر: دوره‌ها، پیشرفت، آزمون‌ها، تمرین‌ها، گواهی‌ها، فعالیت‌ها منتقل می‌شوند.

## عکس پروفایل
منبع عکس (`my` / `edu` / بدون) ذخیره می‌شود. عکس my در هر ورود همگام می‌شود مگر کاربر در edu عکس خودش را آپلود کرده باشد. تغییر عکس در edu **هرگز** به my ارسال نمی‌شود. کاربر می‌تواند از پروفایل به عکس my برگردد.
